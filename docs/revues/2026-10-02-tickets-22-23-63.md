## #22 — moteur d’overlay : OK avec réserves après corrections

- **P1 corrigé — fenêtre macOS sans bordure rejetée.** Pendant la personnalisée
  réelle, connexion LCU, données Live, activation et premier plan étaient valides.
  CoreGraphics donnait la fenêtre LoL au niveau 1000 ; le filtre n’acceptait que 0.
  Le panneau fixé au niveau 3 serait également resté derrière le jeu. La sélection
  reconnaît maintenant les couches 0/1000 du processus LoL confirmé ; le panneau
  suit aux niveaux 3/1001. Le cache inclut le niveau, même à rectangle identique.
  Test de régression rouge puis vert, correctif chargé dans l’app. Confirmation
  visuelle obtenue : l’utilisateur voit le panneau dans sa personnalisée.
- **P2 corrigé — affichage Windows activant.** `window.show()` descendait dans
  Tao jusqu’à `ShowWindow(SW_SHOW)`. Affichage et masquage passent désormais tous
  deux par `SetWindowPos` avec `SWP_NOACTIVATE` ; ils ne dépendent pas du cache
  interne de visibilité de Tao. Recette Windows toujours nécessaire.
- **P2 corrigé — tests du moteur absents de la commande globale et de la CI.**
  `pnpm test` inclut maintenant `cargo test -p olc-desktop --lib`, ainsi que les
  jobs desktop Windows/macOS après compilation des ressources frontend.
- **P3 corrigé — alerte de raccourci persistante.** La disponibilité du raccourci est
  conservée séparément du résultat de sauvegarde, avec test rouge puis vert.


Le détachement WebKit avant conversion NSPanel, le rattachement dans le matériau
AppKit et la rétention des vues ont aussi été relus. Aucun blocage supplémentaire
